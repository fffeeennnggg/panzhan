## 值得继续研究的开源项目

| 项目 | 可参考的部分 | 证据与边界 |
| --- | --- | --- |
| [fish2018/pansou](https://github.com/fish2018/pansou) | Go 搜索适配器、TG 聚合、异步结果、缓存 | 已有本地源码研究，MIT 许可；适合作为独立程序的能力参考，不必捆绑服务 |
| [ucmao/pan-relay](https://github.com/ucmao/pan-relay) | SQLite 本地资源库、API/TG/插件搜索、转存流程 | 当前研究主要来自 README，尚未逐文件审计；它的分发转存用途不等同于 NAS 下载器 |
| [huanyu-a/panseek](https://github.com/huanyu-a/panseek) | PanHub 衍生的 Nuxt 全栈搜索、优先级、熔断与缓存思路 | 不属于全新独立来源生态；README 标注 MIT，但本轮未取得可核实的 LICENSE |
| [unilei/aipan-netdisk-search](https://github.com/unilei/aipan-netdisk-search) | Nuxt、PostgreSQL/Prisma、本地资源管理与外部 API | 适合参考持久资源库方向；复用前核对具体版本许可，不能套用分叉仓库的许可结论 |
| [myh789/pan-search](https://github.com/myh789/pan-search) | 可配置 API/TG/网页来源、本地资源和转存 | 属于 xinyue-search 衍生项目，README 说明不内置来源；不能当作开箱即用的数据源集合 |
| [wu529778790/panhub.shenzjd.com](https://github.com/wu529778790/panhub.shenzjd.com) | 流式结果、分批展示、继续搜索等前端交互 | 当前公开源码为调用站点 API 的前端，不能认为部署它就拥有线上站点完整后端；PolyForm Noncommercial |

不要把只有发行包的仓库直接算作完整开源项目。Xwudao/go-pansearch-release 的完整后端源码尚未核实。PanSou 中名字接近云搜的插件也不能仅凭名称认定使用 yunso.net。

## 对盘栈的建议

1. 数据层：持久保存成功解析的结构化资源，记录来源、网盘、分享 ID、发现时间、最近检查时间及失效状态。缓存命中先展示，外部搜索补充。资源发布时间与采集时间应分别存储。
2. 调度层：保留并发、取消和渐进结果能力，补齐逐来源健康状态、超时隔离、退避和熔断。单个来源失败不应让整页搜索失败。
3. 展示层：默认夸克筛选，提供相关度/时间排序、关键词高亮；同一分享 ID 合并来源，不能只按同名标题合并不同资源。
4. 操作层：只有已解析且受支持的分享链接进入“转存并下载”；待解析、失效或需要用户验证的条目分别说明状态。链接预检按需进行，避免首屏等待所有链接校验。
5. 性能验证：分别记录首条结果时间、搜索结束时间、来源成功率、可解析分享链接率、转存成功率。界面优化不能替代数据源可用性。

这些是盘栈的实现建议，并非对云搜后端架构的断言。推荐参考 PanSou 的 Go 搜索层、资源库项目的持久化模型和云搜的交互方式，在盘栈内实现；不要求将这些项目作为独立服务一并打包。
