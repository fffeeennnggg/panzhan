# 0.1.2 安装密码与保留配置修复

用户反馈：安装向导设置了管理密码，打开应用仍提示密码不正确。

已复现的缺陷：0.1.1 启动时，仅在 `state.json` 尚无密码哈希的情况下消费 `bootstrap-password`。fnOS 若保留旧数据，安装回调虽写入新密码，服务却继续使用旧哈希，并删除新密码临时文件。保留旧配置的测试中，新向导密码返回 401。

修复：只有飞牛安装/设置向导明确写入了一次性密码文件，才更新现有状态中的密码盐和哈希；普通重启和只覆盖升级不会改变密码。更新不创建替代 master.key，不清空网盘账号、任务或设置。

飞牛应用中心的配置向导改为可重新设置管理密码。它复用安装回调校验并暂存输入，正常停止服务后重新启动以应用密码。如果停止失败则删除待应用密码并提示重试，避免随后意外生效。

已有 0.1.1 用户的恢复步骤：

1. 手动安装 0.1.2 覆盖升级，保留应用数据，无需卸载。
2. 飞牛应用中心 → 盘栈 → 设置，填写并确认想使用的管理密码。
3. 保存并等待应用重启，用刚设置的密码登录。

验证覆盖：保留旧配置的新密码登录成功、旧密码失效、普通重启不修改密码、无效新密码不破坏旧哈希、ASCII/中文/含空格与符号的密码、账号仍可解密、master.key/任务/设置保留、一次性明文文件删除。新测试在旧实现上失败，修复后通过。

最终验证：`go test ./...`、`go vet ./...`、17 项前端测试通过；Edge 离线浏览器五页流程在 1024、720、360、320px 通过且无脚本异常。用最终 FPK 提取的安装回调和 Linux 二进制，执行“首次设置→登录→正常停止→保留状态再设不同密码→重启→新密码登录成功、旧密码拒绝”，全部通过；未对用户 NAS 进行远程操作。
