# 飞牛网盘资源下载应用：调研与设计草案

日期：2026-10-15。状态：已被用户纠正并撤回，不作为后续实现依据。

> 用户明确要求调研并提取所需源码能力，开发全新的程序，而非打包或调用 AList、PanSou、QAS 整套服务。本文原先推荐的内置服务方案不符合该要求。最新依据见 [能力提取调研](../../research/2026-10-15-capability-extraction.md)。第一版先打通夸克及目标 x86_64 的要求仍有效。

## 1. 目标与已确认范围

提供可安装到飞牛 fnOS 的 FPK 应用。用户搜索资源、选中一个夸克分享、指定 NAS 目录后，应用自动转存到用户自己的夸克网盘，再通过 AList 复制为 NAS 上的真实文件。

用户已确认：第一版先完成夸克的“搜索 → 选择资源 → 转存 → 下载到 NAS”完整链路。其他网盘保留扩展接口，第一版不宣称支持它们的自动转存下载。搜索无法覆盖全网所有资源，应明确展示来源、网盘类型与搜索失败状态。

当前工作目录为空，未初始化 Git；没有既有代码或可复用的本地打包配置。

## 2. 已核实的上游能力

| 项目 | 核实结果 | 第一版用途 |
| --- | --- | --- |
| [AList](https://github.com/AlistGo/alist) | 多存储管理；跨存储复制通过源链接读取数据并写入目标存储 | 保留其夸克到本地存储的复制链路 |
| [quark-auto-save](https://github.com/Cp0204/quark-auto-save) | 自动转存、过滤、整理；提供第三方调用接口 | 转存适配器调用上游接口，保留版权和许可证 |
| [PanSou](https://github.com/fish2018/pansou) | 网盘搜索 API，支持来源插件、结果分类、缓存 | 自托管搜索后端，第一版筛选夸克结果 |
| [PanHub](https://github.com/wu529778790/panhub.shenzjd.com) | 聚合搜索交互；README 说明获取操作依赖独立 wx-auth 服务 | 参考交互流程，自建 NAS 界面，不依赖其公网认证或搜索服务 |

关键源码证据：

- [AList 跨存储复制](https://github.com/AlistGo/alist/blob/main/internal/fs/copy.go)：递归目录会创建子任务；文件复制获取链接、构造可读取的数据流、写入目标存储。父目录任务结束不能单独证明全部文件下载完成。
- [AList 夸克驱动](https://github.com/AlistGo/alist/blob/main/drivers/quark_uc/driver.go)：区分转码地址与原文件下载链接；第一版下载使用原文件，避免把转码内容当成原始文件保存。
- [QAS 的 AList 同步插件](https://github.com/Cp0204/quark-auto-save/blob/main/plugins/alist_sync.py)：已有向 `/api/fs/copy` 提交源目录、目标目录和文件名的实现。调用成功只代表提交结果，应用需继续核实上游业务状态和实际文件。
- [QAS API 文档](https://github.com/Cp0204/quark-auto-save/wiki/API%E6%8E%A5%E5%8F%A3)：包括添加任务与立即执行入口。需要基于锁定版本验证实际完成信号，不把添加任务响应当成转存完成。
- [QAS 插件文档](https://github.com/Cp0204/quark-auto-save/wiki/%E6%8F%92%E4%BB%B6%E9%85%8D%E7%BD%AE)：另有直链推送 aria2 的方案，可作后续对照实验；第一版优先保留用户已体验过的 AList 链路。

源码只能证明处理方式，不能证明用户设备上的速度。实际吞吐受账号权限、上游接口、网络、文件、磁盘与驱动版本影响；不承诺固定速度或绕过网盘限速。

## 3. 三种实现方式

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| A：原生 FPK 管理统一界面、调度器及内置服务进程 | 用户安装一个应用；可控制版本、目录权限和生命周期 | 需为目标 CPU 打包服务和 Python 运行环境，逐个验证 fnOS 兼容性 | 推荐作为完整产品形态 |
| B：FPK 管理 Docker Compose 服务 | 容易复用上游容器，较快开展联调 | 依赖 Docker、镜像可达性和目录映射，分发体积与资源开销需实测 | 原生运行环境不适配时的备选 |
| C：FPK 仅连接用户已有的 AList、QAS、PanSou | 包小，能复用现有部署 | 用户需独立配置多个服务，完整安装体验较弱 | 开发联调模式可支持 |

推荐 A，并在开发阶段先提供 C 的连接方式验证真实接口。尚未确认设备架构和系统版本，因此 A 是待验证的部署选择。

## 4. 推荐架构

应用新增部分：Go 后端、SQLite 任务数据库、Vue 3 + TypeScript 界面；前端构建为静态文件随后端交付。后端统一处理登录、搜索、任务、目录映射与上游调用。此技术选型为草案。

组件边界：

1. 搜索适配器：只负责调用自托管 PanSou、统一结果字段与按分享链接去重。搜索源超时不阻塞已返回结果。
2. 转存适配器：调用锁定版本 QAS，把所选分享转存到该任务专属夸克目录，获得可核实的远端文件清单。
3. AList 适配器：刷新并核对任务目录，将夸克文件复制到已授权的本地存储映射；查询复制任务及子任务。
4. 调度器：保存任务与文件状态、控制并发、处理重试和重启恢复；完成判断由调度器统一负责。
5. FPK 生命周期管理：管理进程启动、停止、健康检查、持久化配置和升级。内部服务优先只在本机监听，用户使用统一入口。

QAS 只负责转存，调度器负责提交 AList 复制，关闭 QAS 的自动复制与 aria2 下载功能，避免同一文件被重复下载。

## 5. 用户流程与界面

首次启动：设置管理密码 → 配置夸克账号凭据 → 测试转存与 AList 访问 → 授权 NAS 下载根目录 → 设置搜索源。

第一版设置中输入账号 Cookie；扫码登录不作为首版交付承诺。凭据只交给本机必要组件，应用界面和诊断日志不回显完整凭据。

主要页面：

- 资源搜索：关键词搜索、夸克结果、来源、分享链接、提取码与“下载到 NAS”操作；支持直接粘贴分享链接。
- 新建任务：选择下载目录、任务名称，明确展示夸克转存位置与 NAS 保存位置。首版按整个分享或分享子目录下载，不承诺任意文件多选。
- 下载任务：展示排队、转存中、等待目录可见、下载中、校验中、完成、失败和取消；提供失败重试、取消和错误原因。
- 设置与诊断：账号状态、目录授权、服务连通性、并发限制和脱敏日志。

默认保留转存到网盘的文件；取消任务停止后续处理并尝试取消对应复制任务，已转存文件和本地已有文件不自动删除。

## 6. 数据链路与恢复规则

主链路：

`搜索 / 粘贴分享 → 创建持久化任务 → 校验分享 → 转存到任务专属目录 → 核实远端文件清单 → 刷新 AList 目录 → 按文件提交复制 → 跟踪复制任务 → 核实本地结果 → 完成`

- 每个应用任务生成唯一 ID，并保存来源分享、提取码引用、远端任务目录、目标目录、上游任务 ID 和逐文件状态。
- 每个目标目录下同一来源文件只允许一个活动下载；相同来源重复点击时返回已有活动任务。
- 转存接口超时后先检查远端任务目录，核对已有结果，再决定重试；不能直接重复执行可能产生副本的转存。
- 转存后进行有截止时间的目录可见性重试；不以固定等待几秒替代结果检查。
- 尽可能逐文件提交复制，保存每个任务的上游 ID；目录递归创建的子任务必须纳入完成判断。
- 上游 HTTP 成功、业务响应成功、任务执行完成、本地文件核实是不同阶段，分别处理。
- 本地完成至少检查预期相对路径和文件大小；上游提供可信哈希时再比较哈希。大小一致不能称为完整性哈希校验。
- 已存在同名文件只有在本应用记录可证明相同来源且已完成时才跳过；其他冲突默认停止该文件并提示，避免静默覆盖。
- 重启后核对保存的上游任务状态和本地文件；找不到上游任务时重新核实结果，再决定恢复或提示处理。
- 复制失败后先核实本地部分文件，重试策略必须经真实 AList 版本测试；首版承诺任务恢复与失败重试，不提前承诺字节级断点续传。
- 账号失效进入等待用户更新凭据；限流采用有上限的退避，不高频重复请求。

## 7. NAS 目录与 FPK 约束

NAS 真实目录、AList 虚拟目录、夸克文件夹 ID 分开保存。后端根据授权根目录映射目标，不接受前端任意指定系统路径。对相对路径、符号链接和目标真实路径进行边界检查。

应用采用专用运行身份，下载目录需授予该身份写入权限。安装和升级保留配置与任务数据；卸载不默认删除用户下载的文件。资源目录不写死某台 NAS 的卷号。

拟使用官方 fnpack 构建 FPK，并配置 manifest、入口、权限、资源和生命周期脚本。当前研究工具无法访问飞牛官方开发站，具体字段、可用运行时、入口行为和最低系统版本仍需在开发时核对官方文档与 fnpack 实际输出；本草案不宣称 FPK 已构建或安装验证。

## 8. 上游版本与分发

实现前固定所用上游版本和校验值，并记录源码、构建方式与修改内容，避免运行时自动跟随 latest。

AList 仓库标示 AGPL-3.0；QAS README 标示 AGPL-3.0 并另有用途声明。PanSou LICENSE 为 MIT，而 README 另有用途提示。PanHub README 标示 PolyForm Noncommercial 1.0.0。因此计划保留上游署名与许可证，第一版自建界面，不复制 PanHub 代码；实际分发前逐项核对锁定版本文件，不能仅凭项目名称推定许可，也不把服务拆分当成自动免除许可义务。

## 9. 实施顺序与验收

1. 确认系统版本、CPU 架构及可用测试环境；验证同一 NAS 上 AList 原文件复制的速度与落盘结果。
2. 用开发连接模式打通分享转存、远端目录确认、AList 复制与本地核实；先验证最小真实链路。
3. 增加 SQLite 状态机、逐文件记录、重试、取消、重启恢复和目录授权。
4. 增加搜索适配器、统一界面和首次配置向导。
5. 构建原生 FPK 的运行环境与生命周期脚本；在目标 fnOS 上安装、启动、升级、停止和卸载验证。

自动测试重点：接口业务错误、转存后目录延迟、重复点击、目标冲突、凭据失效、路径越界、父任务完成而子任务未完成、重启后状态核对。模拟测试用于验证调度逻辑，不能替代真实网盘和 fnOS 验收。

真实验收：用用户有权访问的分享，在目标 NAS 下载单文件和嵌套目录；检查真实文件、大小、任务状态及失败恢复。大文件测速需记录账号、驱动版本、文件大小、耗时、平均吞吐和磁盘状态，与相同环境下手动 AList 复制对照。

交付完成标准：源码与构建说明、版本固定记录、目标架构 FPK，以及上述真实链路与安装验收记录。未取得设备或账号测试条件时，明确标记未验证项目，不能将可运行的模拟界面算作完整应用。
