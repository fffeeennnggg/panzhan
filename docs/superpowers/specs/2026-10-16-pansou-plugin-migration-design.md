# PanSou 搜索插件迁移设计

日期：2026-10-16。状态：用户已确认迁入 issue #4 的 67 个插件。

## 目标

扩大盘栈的资源搜索覆盖面，将 issue #4 的 67 个 PanSou 搜索插件作为盘栈进程内的来源适配器编译注册。盘栈继续提供自己的认证、搜索 API、结果页面、资源库、夸克预览、转存和 NAS 下载；不运行 PanSou HTTP 服务，也不把结果请求转发给 PanSou 服务。

## 源码事实

- PanSou 插件是 Go 编译期注册的适配器，不是可以从 issue 清单直接安装的脚本包。
- issue #4 的 67 个启用名称均能在本地研究源码的 `plugin/` 下找到；其中至少一个并未出现在 PanSou 当前 `main.go` 的活跃 blank-import 列表。迁移以 issue 清单为基准，单独显式注册这 67 个名称。
- 插件返回标准结果，结果内可以有多个网盘链接、提取码、发布时间和 `work_title`。盘栈首版只将 `type=quark` 的分享链接送入夸克检查与下载流程；其他网盘不伪装成可转存夸克。
- PanSou 插件含需要额外账户或插件自身 Web 管理路由的来源（例如 QQ 频道）。没有对应凭据配置时，来源仍须在列表中显示明确的未配置或无结果状态，不能声称全部来源在线可用。

## 架构

1. 在 `internal/search` 增加统一 `SourcePlugin` 契约，字段包含稳定 ID、显示名、优先级和可取消的搜索方法。当前 HTTP/HTML 适配器通过薄包装加入同一注册表；PanSou 迁移源通过共享桥接层调用对应插件。
2. 从 PanSou MIT 源码中迁入插件实现和其必要的模型、基础插件、配置与工具代码，保留逐文件版权声明及 MIT 许可证。排除 PanSou 的 `main`、HTTP API、认证、独立缓存服务和 Web 服务器。所有迁入源码使用盘栈内部模块路径，并在 `THIRD_PARTY_NOTICES.md` 中列出锁定来源、迁入范围和修改方式。
3. 应用启动时显式注册 issue #4 的 67 个适配器。插件失败彼此隔离，错误、耗时、缓存与结果数继续通过现有 `/api/search` 状态返回；搜索请求由浏览器保持逐来源并发与渐进展示。
4. 结果归一化只保留安全的 HTTPS 夸克分享；优先采用 `work_title`，其次采用插件结果标题；把结构化 `Password` 合并进规范化分享 URL。相同分享按现有分享 ID 去重并合并来源。
5. 将插件优先级用于首轮调度和结果排序；稳定排序必须保留同级原始顺序。插件专属配置不能未经授权暴露为任意环境变量或开放路由；本轮先标注所需配置，后续按真实凭据需求逐项接入。
6. 新安装默认启用 issue 清单来源和现有 Telegram 公开频道。升级时保留用户自定义启停项；只有原设置仅含旧默认 `pansearch` 时迁移至新默认集合。

## 验收

- 编译期注册的 PanSou 来源 ID 与 issue #4 的 67 个名称完全一致，无缺项、重复或隐藏未注册项。
- 单个插件报错不影响其他来源；超时、取消、部分结果和空结果状态语义明确。
- 归一化测试覆盖 Quark、其他网盘过滤、提取码、`work_title`、非法域名与重复分享。
- 源级调度与搜索结果排序体现插件优先级且稳定。
- 既有 source 设置、来源 API、暂停/继续、增量结果、资源库和下载任务测试继续通过。
- `go test ./...`、`go vet ./...`、Linux amd64 构建与 FPK 暂存检查通过。真实来源是否在线仍通过来源状态报告，不把编译通过等同于公网源可用。

## 范围边界

本次目标是迁入并注册完整 67 个适配器，不承诺 67 个第三方站点在同一网络、同一时刻均可访问。需要 QQ 登录、Cookie、验证码或专属管理流程的来源必须明确配置前置条件。其他网盘链接可显示为不可转存候选，第一版下载仍限夸克。
